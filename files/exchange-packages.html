    Exchange packages#

    Last edited October 21, 2026

    Exchange packages carry measurements, interior models and solutions between teams, for example in a blind test where one team simulates measurements of an interior it keeps hidden and other teams invert them. They are plain text with the units, frame and normalization written in them, and can be read without SBTK.

    Package Name Written by Contents Released
    Measurements <team>-DATA<n>-<comment> sbtk.exchange.write_data Gravity field, covariance, center of mass, moments of inertia, shape model with the data set
    Interior model <team>-MOD<n>-<comment> sbtk.exchange.write_model True model, density grid, noise-free measurements, figures after the solutions
    Solution <team>-SOL_<data team><n> sbtk.exchange.write_solution Estimated densities, covariance, fitted measurements, density grid, figures with the solution

    sbtk.exchange.solution_name forms solution names; sbtk.exchange.locate finds the package of a given kind in a run folder and its redacted/ and unredacted/ subfolders.

    File layout#

    Each file starts with metadata lines # key: value, followed by one line of column names and comma-separated rows. Every column and key with a unit ends with it; NaN marks a value that is not provided.

    Reader Statement
    MATLAB T = readtable('gravity_field.txt', 'FileType', 'text', 'CommentStyle', '#');
    Python with pandas T = pandas.read_csv('gravity_field.txt', comment='#')
    Python, standard library rows = list(csv.DictReader(l for l in open('gravity_field.txt') if not l.startswith('#')))
    SBTK sbtk.exchange.read_data(folder), sbtk.exchange.read_grid(file)

    Measurement package#

    File Contents
    README.txt Summary (GM and mass, bulk density, degree and reference radius of the field; the uncertainties and the noise when the values have them) and the list of files.
    gravity_field.txt l,m,C,S, fully normalized, with sigma_C,sigma_S when the values have uncertainties: from degree 1 about the origin of the shape model file, or from degree 2 about the center of mass (Expansion point).
    gravity_field_unnormalized.txt The same coefficients unnormalized, Clm=NlmC¯lm, Slm=NlmS¯lm (Gravity coefficients), and their 1σ when they have one.
    gravity_covariance.txt Full covariance of the normalized coefficients; rows and columns labeled. Only when the values have uncertainties.
    center_of_mass.txt Center of mass in the shape-model frame (with its 3 × 3 covariance when it has one) and the center of figure.
    moments_of_inertia.txt quantity,value,unit (and sigma): inertia elements as I/(MRref2) about the same point as the gravity field and/or the libration ratio. The products of inertia are tensor elements, Ixy=−∫ρxydV (Moments of inertia); the definition of the libration ratio is given when the file has it.
    conventions.txt Units; the frame (what its origin and axes are, and any change of frame from the original shape-model file); the normalization, with MATLAB and Python code; degree 1 and the center of mass.
    <shape>.obj The shape model the data were made with, in km, in the frame of every position of the package (The shape model of a package). Not included when it is one of SBTK's shape model files as distributed (data/shapes/), such as the agreed HLP6 models: the files then name it.
    potential_acceleration.txt Optional (sbtk.exchange.write_potential): the gravitational potential and acceleration at given points, in SI units (Potential and acceleration at points).

    The package contains nothing about the interior: not the noise seed, the model name or any component; testNothingAboutTheInterior checks this (Validation).

    Expansion point#

    The gravity field and the moments of inertia are given about one of two points, chosen by the measurement set that sbtk.exchange.write_data writes:

    Point Measurement set gravity_field.txt sbtk.exchange.read_data returns
    The origin of the shape model file (the HLP6 choice) about [0 0 0], e.g. from sbtk.data.expand_about degree 1 and above; degree 1 gives the center of mass the coefficients as given, coef_about = 'origin', origin_km = [0 0 0]
    The center of mass, as a radio-science solution any other set degree 2 and above; degree 1 is zero and not listed degree ≥ 2 about the measured center of mass, degree 1 as 0 ± σ (the uncertainty of the center of mass), coef_about = 'center_of_mass'

    center_of_mass.txt gives the center of mass and the center of figure in both, and conventions.txt states which point the package uses. The body is built from the package's shape model and GM; sbtk.exchange.read_data reads the shape model from the package, or from data/shapes/ when the package names a file it does not include. A libration ratio, which is defined about the center of mass, becomes the row (B−A)−kIzz=0 with σ = σkIzz, using the measured Izz if the package has one and that of a homogeneous body otherwise.

    The files state only what applies to the package. Those of a measurement package with uncertainties and noise, made by documentation/tools/make_samples.m:

    The shape model of a package#

    A package's shape model is the one the data were made with, in the frame of every position of the package. The HLP6 makers use the agreed shape model file as distributed, unchanged, in its own frame (Frames of a gravity field). Every team has that file, and it never changes, so a package made with it does not include it: README.txt and the header of every file name it. ex09) sends the original shape model moved and rotated into the new frame with sbtk.body.to_frame: every vertex becomes x′=(x−c)A, with c the center of mass of the true model and the columns of A the new axes, both in the frame of the original file. The shape itself does not change, only its coordinates.

    Example Shape model of the package Origin Axes
    Didymos, spin axes TEAM-DATA1-Didymos_didymos_v003_com_spin_axes.obj center of mass z the axis of the largest moment, x the DART x-axis projected onto the plane normal to z
    Dimorphos, principal axes TEAM-DATA2-Dimorphos_dimorphos_v004_com_principal_axes.obj center of mass principal axes: x the axis of the smallest and z of the largest moment

    Each true model has its own center of mass and axes, so each package has its own shape model, and its file name starts with the name of the package: <package>_<shape name>.obj (sbtk.internal.shape_file_name). The interior-model package of the data set and a solution of it use the same name. A shape model taken unchanged from a file keeps the file's name.

    The center of mass is then at the origin (to rounding), and the center of figure at −(rCoM−rCoF)A. The gravity field, the moments of inertia and center_of_mass.txt, and in the interior-model package every component and the density grid, are in this frame, so a receiving team uses the shape model as it is, with nothing to move or rotate. The FRAME section of conventions.txt states the origin and the axes, and the change of frame from the original file (o=c and A), so the coordinates of the original file are x=x′AT+c. The shape model records this change as shape.frame_origin_km and shape.frame_axes, combined over successive changes of frame. The FRAME section of such a package, made by documentation/tools/make_samples.m:

    Potential and acceleration at points#

    sbtk.exchange.write_potential adds potential_acceleration.txt to a package: one row per point with its position x_m,y_m,z_m in the frame of the shape model file, the potential U_m2_s2 and the acceleration ax_m_s2,ay_m_s2,az_m_s2, in SI units as the HLP6 makers' cross-validation asks. The potential is positive, U=G∫ρ/|r−r′|dV, the acceleration is its gradient, and the rotation of the body is not included. The header states how the values were computed (sbtk.gravity.field_at): exactly for a homogeneous body, otherwise with the departures from the background density on a grid of cubes (Potential and acceleration at points). The function works for any model; the HLP6 makers give it for the homogeneous Didymos (examples/make_didymos_homogeneous.m).

    Packages of exact values#

    A set without any uncertainties, such as the exact values of a true model (sbtk.data.simulate), is written as a package of exact values:

    • gravity_field.txt has the columns l,m,C,S, center_of_mass.txt the columns axis,center_of_mass_km,center_of_figure_km, and moments_of_inertia.txt the columns quantity,value,unit;
    • there is no gravity_covariance.txt;
    • no file has an uncertainties or noise line.

    A maker's package of exact values in the frame and about the origin of the shape model file, as the HLP6 makers send them, made by documentation/tools/make_samples.m:

    In a blind test the makers send such packages, and each receiving team applies uncertainties of its own choosing. sbtk.exchange.read_data reads them with NaN uncertainties. The inversion then stops with sbtk:data:noUncertainties until uncertainties are given, for example with sbtk.data.use_uncertainties from a precision file and sbtk.data.set_moi_sigma, after truncating with sbtk.data.select_degree to the degrees the precision covers. A set with some uncertainties but not all is not written (sbtk:data:noUncertainties).

    Density grid#

    Cell centers lie at integer multiples of spacing_km along each axis of the shape-model frame, so grids of the same spacing coincide regardless of who made them. A cell is listed when its center is inside the shape model, tested along rays from the center of figure, so all models of a body have the same cells. Each cell stands for the volume spacing_km³ and carries the density at its center. sbtk.compare.grids compares two grids (Comparison of density grids); the comparison of the example solution with its model:

    Output
    density grids: 3179 common cells (3179 true, 3179 estimated)
  R2 = 0.922 (fraction of the variance of the true density explained)
  RMS error 98.3 kg/m^3, mean error +1.2 kg/m^3, standard deviation of the true density 351.3 kg/m^3
  97.9% of the common cells have abs(estimate - true) <= 2 sigma of the estimate

    conventions.txt#

    Every measurement package includes this file, written by sbtk.internal.exchange_conventions; the tests check the normalization code it prints. That of the maker's package above, in the frame and about the origin of the shape model file:

    Output
    UNITS
  Lengths and positions in km, mass in kg, time in s, GM in km^3/s^2, densities in kg/m^3,
  angles in degrees.

FRAME
  All positions, the gravity field and the moments of inertia of this package are given
  in the frame of its shape model file, didymos_g_9309mm_spc_obj_0000n00000_v003.obj:
    origin  the origin of the shape model file (different from the CoF and CoM)
    axes    those of the shape model file as distributed

GRAVITY FIELD COEFFICIENT NORMALIZATION
  The files give fully normalized coefficients:
    Cbar_lm = C_lm / N_lm,   Sbar_lm = S_lm / N_lm,   Pbar_lm = N_lm P_lm,
    N_lm = sqrt( (2 - delta_m0) (2l + 1) (l - m)! / (l + m)! )
  where P_lm are the associated Legendre functions without the factor (-1)^m. For example,
    N_20 = sqrt(5), N_21 = sqrt(5/3), N_22 = sqrt(5/12), N_30 = sqrt(7).
  Zonal coefficients: J_l = -C_l0 = -sqrt(2l + 1) Cbar_l0.
  gravity_field_unnormalized.txt gives the same coefficients unnormalized:
    C_lm = N_lm Cbar_lm,   S_lm = N_lm Sbar_lm.

  MATLAB
    N = sqrt((2 - (m == 0)) .* (2*l + 1) .* factorial(l - m) ./ factorial(l + m));
  Python
    N = math.sqrt((2 - (m == 0)) * (2*l + 1) * math.factorial(l - m) / math.factorial(l + m))

DEGREE 1 AND THE CENTER OF MASS
  The gravity field is expanded about the origin of the shape model file. Its degree-1
  coefficients give the center of mass (xc, yc, zc) relative to that origin. The moments
  of inertia are about the same origin.
